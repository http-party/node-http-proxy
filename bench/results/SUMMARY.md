# Optimization results — BASELINE (1.18.1) vs CANDIDATE

Generated by the `bench/` + `evals/` suite on Node `v24.16.0` (unpinned macOS
dev box). Per the panel's design, results are split into **certifiable**
(deterministic) and **inconclusive** (wall-clock, noise-gated) signals.

## ✅ Certifiable signals (deterministic)

### Microbench — `setupOutgoing` per-request hot path
Network-free, GC-contamination-filtered, 0% A/A null delta.

| Metric | Baseline | Candidate | Δ |
|---|---:|---:|---:|
| ns/op | ~1240 | ~890 | **−28.3%** |
| bytes/op | 2674 | 2033 | **−24.0%** |

Attributable to: `Object.assign` over `util._extend`, hoisting the TLS-key
array + de-closuring the copy loop, and skipping `url.parse` for origin-form
paths.

### Leak gate — WebSocket teardown (differential vs baseline)

| Case | Baseline leak | Candidate leak |
|---|---:|---:|
| leak gate (300 WS churn cycles) | **601 handles** | **1 handle** |
| lifecycle half-open-upgrade | 41 | 1 |

The upstream socket leak on client disconnect is effectively eliminated.

### Correctness gates
- Wire oracle: **15/15** client-visible responses byte-identical to baseline
  (incl. backslash/space path-normalization security guards).
- Lifecycle: survives client-abort / origin-RST / slowloris / half-open upgrade.
- Core unit tests: **110 passing**, 2 failing (both pre-existing on pristine
  1.18.1 under Node 24 — a timeout test and a follow-redirects test; not caused
  by these changes).

## ⚠️ Inconclusive signals (not certifiable on this box)

The A/A self-calibration reported a 27–137% null delta with CoV 14–45% — the
unpinned dev box is too noisy to certify network-level tail-latency deltas. The
suite therefore marks `small-keepalive` (p99.9) and `mixed-prod` (p99) as
`no-change` regardless of the raw numbers, and `large-streaming` RSS was flat
(~0.4%). **These require the Tier-2 pinned/bare-metal lab to certify** — the
microbench is the portable stand-in for the per-request CPU/alloc win.

## What was deliberately NOT changed

- **Default keep-alive agent** — the single biggest real-world throughput win,
  but it removes the forced `Connection: close` and therefore changes the wire
  (the oracle would flag it). It is a behavioural/semver decision for the
  maintainer, not a transparent optimization. Recommended as a documented
  opt-in / next-major default.
- **`req.connection` → `req.socket`** — no measurable benefit, and it breaks
  test fixtures that mock only `connection`; not worth the risk for this lib.
- **Monomorphic `outgoing` shape** — plausible but **not certifiable** with the
  current single-shape microbench; would need a polymorphic-shape bench first.
